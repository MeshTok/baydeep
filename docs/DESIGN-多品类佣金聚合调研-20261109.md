# DESIGN — BayDeep 多品类佣金聚合调研（API × 佣金 × 国内收款三重筛）

> 2026-11-09 调研定稿。目标：给 agent 聚合尽可能多的能力（商品/旅行/机票/酒店/活动/数字服务/保险），
> 每一条都过三重门槛：①API 可调（agent 能程序化集成）②佣金真实 ③**结算能到国内账户**。
> 检索经多轮交叉验证；个别标注「待注册验证」的以注册后控制台实见为准。

---

## 一、硬前提：收款基础设施（一次办定，全通道打通）

| 通道 | 覆盖 | 状态 |
|---|---|---|
| **Payoneer 派安盈** | Travelpayouts / Admitad / eBay(Tipalti) / CJ 系 / Walmart / 大多数欧美网络；支持 **CNY 收款账户**提现国内 | ⏳ 必办（第一优先） |
| **WorldFirst 万里汇** | 阿里系（速卖通已通）/ TikTok Shop | ⏳ 必办 |
| 国际支付宝 | 速卖通联盟备用 | ✅ 已通 |
| PayPal | 欧美网络默认付款方式；国内提现麻烦（连连/Payoneer 中转） | 劣后 |
| 银行电汇 T/T | Travelpayouts/大网络兜底（手续费 $15-40，Travelpayouts 出网费） | 兜底 |

税务：美国系平台在线填 **W-8BEN**（个人）/W-8BEN-E（公司）；个人年度结汇 $5 万额度，量起后转公司主体+对公。

|---|---|---|---|---|---|

| **TikTok Shop 联盟** | 商品（达人带货） | 按类目 | 联盟链接（API seller-gated） | Payoneer/WorldFirst | 内容型 agent 场景强 |

### T1 —— 有门槛/谈判型（有真实 API，达标后再上）

| 平台 | 门槛 | 策略 |
|---|---|---|
| **Expedia Rapid API**（70 万+ 酒店，购物→预订→支付全链） | 审核制：流量/商业模式/技术评估 + 上线认证 | 有流量后申请；TAAP 需 IATA/ARC 资质（不适用我们） |
| **Klook Partner（KDP）** | 谈判型 travel API（分销商/OTA 向）；公开侧只有 affiliate.klook.com（2–8%，无 API） | 先接公开联盟（链接级），有量谈 KDP |
| **CJ / Awin / impact / Rakuten / Sovrn** | 逐家申请审核；各有 **Product Catalog API**（CJ Product Catalog / Awin Product Feed / impact Catalog） | Sovrn 一次接入 5 万+ merchant（Merchants API/Link Check API），可作为欧美商品聚合备选 |
| **Amazon Associates + PA-API 5** | 入会 180 天 3 单才给 API；展示规则严；收款历史麻烦（Payoneer ACH 中转可解） | 先 SiteStripe 手工链做流量，达标后开 API |

## 三、品类 × agent 叙事（对外话术素材）

给 agent 开发者的聚合叙事从「电商」升级为「**全球消费能力层**」：

> 一个 MCP/REST，让你的 agent 能卖商品、订机票酒店、卖活动票、发 eSIM、配旅行保险——每一单你都拿佣金。

- 商品：AliExpress（✅已通）→ eBay → Walmart → Admitad(Temu/Shein 链接级)
- 旅行：Travelpayouts（机票数据+转链）→ Trip.com（酒店/火车）→ Expedia Rapid（后期）
- 活动：Viator / GetYourGuide
- **数字服务（agent 最适品**）：Airalo eSIM（10–12% 高佣、无物流、即时交付）→ EKTA 保险（日结）
- 同构性：转链归因每家字段不同（source_values/subId/customParameters/Impact clickID）→ 在各自 adapter 内消化，L2 永远感知统一协议（照抄国内 DESIGN §二）

## 四、落地顺序（建议）

1. **Payoneer 注册**（Travelpayouts/Admitad/eBay 都依赖它；支持 CNY 提现）——用户侧，1 天
2. **Travelpayouts 注册**（纯邮箱）→ Flight Data API + Partner Links API 实测 → `adapters/travelpayouts.js`（照 aliexpress.js 模式：call + norm + search/convert/orders）
3. **Trip.com partner 注册** → `adapters/tripcom.js`（酒店/机票搜索+转链）
4. **Airalo Partners API 申请** → `adapters/airalo.js`（eSIM 目录+下单归因；数字商品首批）
5. eBay ePN（既有调研，Payoneer 通道）→ `adapters/ebay.js`
6. Admitad 注册 → Temu/Shein/Viator 链接级转链统一挂进 `convert()` 分发
7. Viator/GetYourGuide affiliate（链接级先行，API 后谈）
8. Expedia Rapid / Klook KDP：有真实流量后谈判
9. 统一商品协议扩展：`category` 字段加 `flight/hotel/activity/esim/insurance` 枚举；L3 MCP 工具面按品类分组

## 五、红线与合规（增量）

1. **平台 terms 逐家确认「程序化/agent 流量」许可**：Travelpayouts 旗下多品牌对 chat/app 流量友好；Airalo 明确支持 API 集成；Booking 类明令禁止——接一家核一家（留存 terms 截图）
2. W-8BEN 税表：美国系平台注册时在线填；金额起量转公司主体（对公+增值税发票链路）
3. 消费者侧绝不出现返现/返利话术（沿用源头淘红线 §四.3）；agent 永不碰钱（资金流=用户→平台→联盟→我们→开发者）
4. 旅行品类注意**价格时效**（机票/酒店库存分钟级变化）——agent 侧展示必须带「价格以结算页为准」免责话术
