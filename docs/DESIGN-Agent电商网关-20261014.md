# DESIGN — Agent 电商网关（源头淘基础设施层定位）

> 2026-10-14 立项。用户判断：淘宝/京东/拼多多对 agent 全封闭，我们通过 CPS 对接再开放给
> 所有 agent，是巨大机会。本文件是这一机会的完整产品设计，后续所有相关迭代以此为准。

---

## 一、机会的本质

**平台为什么封闭**：淘宝/京东/拼多多视 agent 为爬虫与去中介威胁——没有 agent API，
 Robot 协议封禁、风控拦截、购买链路反自动化。直接对接平台=对抗平台，不可持续。

**但它们留了一扇合法的门：CPS 联盟**。淘宝联盟（TBK）、京东联盟、多多进宝存在的
意义就是「把商品与成交开放给外部推广者」——带归因、带结算、官方鼓励放量。三平台的
联盟 API 我们已全部打通（淘宝含 upgrade 版物料搜索 50 页深翻、京东热销榜免配额、
多多进宝全量）。

**于是源头淘的位置**：站在这扇门上，把 CPS 能力**翻译成 agent 协议**——

```
淘宝联盟 ┐
京东联盟 ├──▶ 源头淘网关 ──────────▶ 任意 AI Agent
多多进宝 ┘    · 统一商品库(5万+,每小时长)      (DSH/扣子/豆包/Claude/自研…)
              · 标准化商品协议                   MCP / REST / 各家插件市场
              · 转链与归因(按开发者)
              · 结算(成交额5%开发者分成)
              · MCP + REST 双协议
```

**三方各取所得**：
- **平台**：CPS 是它们主动开放的推广渠道，我们给它带来成交（不碰它的红线：不爬
  非开放数据、不做裸数据转售、经由官方联盟归因）
- **Agent 开发者**：零电商基础设施拿到完整购物能力+变现（成交额 5% 分成）——
  这是当下绝大多数 AI 应用的变现答案
- **源头淘**：归因结算的通道价值 + 商品库的聚合价值 + 「agent 电商第一入口」的先发

**一句话定位**：一个插件，给任何 AI 加上电商能力——商品搜索、比价、购买链接、
订单履约，覆盖淘宝/京东/拼多多。

## 二、分层架构

### L1 平台层（CPS 联盟，唯一合法门）
- 淘宝联盟：tbk 全家桶（物料搜索 upgrade 版/详情/店铺/淘口令/订单/官方活动位）
- 京东联盟：goods.query(配额制,等级升额)/rank.query(免配额)/订单行/转链
- 多多进宝：goods.search(翻页浅)/转链(goods_sign)/订单
- 美团：cps_open 网关（等待平台侧放开，结构已备）
- **约束即设计输入**：各平台配额/频次/字段差异被 L2 吸收，L3 永远感知统一的协议

### L2 源头淘网关层（本设计的核心资产）
1. **统一商品库**：本地货架 5 万+（每小时长），标准化商品协议
   （platform/item_id/title/price_final/coupon/sales/detail_url/attrs），数字与
   加密 ID 双制式兼容
2. **转链与归因**：所有购买链接带渠道归因；按 agent_key 隔离；佣金按 key 归集
3. **结算**：成交额 5% 开发者分成，月结；免注册试用 key 的佣金在绑定开发账号后
   全量跟随（agent_id 家族机制）
4. **协议面**：MCP Streamable HTTP（主）+ REST 同语义（辅）+ llms.txt 机器文档；
   后续按生态追加（如 agent 支付/A2A 类协议出现时）
5. **访问分层**（已上线）：
   | 层 | 门槛 | 能力 |
   |---|---|---|
   | 公开只读 | 无（IP 30/min） | 本地货架搜索/对比/详情/购买链接（不烧平台配额） |
   | 免费 key | POST /trial，永久有效 | 全 20 工具+实时扇出+佣金归因（IP 5 key/日防灌水） |
   | 绑定账号 | 控制台免费注册+绑定码 | 提现 |

### L3 Agent 层
- 接入路径：MCP 配置一条 URL（+可选免费 key）——或直接无 key 试用
- 已覆盖宿主：DeepSeek Harness（dsh-plugin 已发）、扣子/豆包（插件在建）、
  Claude/任意 MCP 客户端、REST 自研 agent
- 分发面：awesome-remote-mcp-servers(PR#1746)、DSH Market(PR 明日自动)、
  各家插件市场（矩阵文案已备 docs/platform-seo-listings.md）

## 三、为什么是我们（护城河）

1. **归因结算网络**：三平台 × N 开发者的佣金归集与分配，一旦跑通就是通道型资产；
   复制者要重新谈的不是一个平台而是「信任与结算」
2. **统一商品协议**：5 万+商品的去重/标准化/价格史，是所有 agent 电商能力的地基
3. **先发卡位**：「agent 电商网关」的生态位置（目录/GEO/插件市场）已被我们占住，
   后来者面对的是既有分发网络
4. **合规姿态**：经由官方联盟、数据只经 API 不爬、佣金透明——这是能长期做下去的前提

## 四、红线（违反即失去 L1 授权）

1. 不爬非开放数据；只使用联盟 API 返回内容
2. 不向第三方转售/转授权原始数据（awesome-dsh-plugin 规范同款约束）
3. 消费者与开发者场景**绝不出现**「返现/返利/佣金」话术（源头淘不提供返利——
   返利是推返；开发者场景只说「成交额 5% 分成」）
4. agent 永不碰钱：资金流=用户→平台→联盟→我们→开发者，agent 只拿链接与归因
5. 各平台配额制度遵守（jd 等级制/pdd 频控），滥用即断供

## 六、对外话术标准（全渠道统一）

- 开发者向：「给你的 AI 加上电商能力——商品搜索、比价、购买链接、履约，成交额 5% 分成」
- 消费者向：「一句话搜全网好价、比价防坑、正品渠道直达」
- 禁用：返现/返利/佣金（消费者场景）；爬虫/抓取/代购（全场景）
- 平台名使用：仅作为「覆盖渠道」陈述，不使用其 logo/品牌做背书暗示
